# Doctor 复检走查脚本

日期：2026-10-02。负责：Product/UI Engineer。
范围：复检结果页（[D1 画面流程 S4](2026-09-16-doctor-d1-screen-flow.md)）。
词表：[复检词表](2026-10-02-doctor-recheck-vocabulary.md)。

## 这是什么，不是什么

这是一份给**不熟悉实现的人**做的走查：只给任务，不给讲解。要回答的问题只有一个——
一位使用 Revit 的 BIM 分包经理，在没人讲解的情况下，能不能从屏幕上说清三件事：
**什么变了、什么仍未解决、下一步做什么**。

- **本脚本尚未执行。** 本文件只是脚本和空白记录模板，不是走查结果，也不是验收结论。
- 这是内部走查，不是目标用户验证。参与者不是真正的分包经理时，照实记在模板里。
- 走查不改 `doctor/`、适配器、Framework、Pack 或规则。发现的问题只记录，不在走查中修。
- 不计算就绪评分，也不给走查本身打分。记录的是原话和卡住的位置。
- **填好的记录不要提交到本仓库。** 模板只要自定的会话代号，不要姓名、公司、
  邮箱或任何能认出人的信息。

## 谁来做

- **参与者**：没有读过 Framework 代码、ADR 或本仓库测试的人。读过的人不合适——
  他们会用已知的东西补上屏幕没说清的地方。
- **主持人**：只念任务、记录原话。**不解释任何词、不指屏幕、不纠正。** 参与者问
  “这是什么意思”时，回答：“请按你的理解说，页面没说清也是我们要记的。”
  如果主持人还是讲解了，在记录里照实写下讲了什么。

## 准备

在一个干净的检出里（提交号由技术总监在安排走查时指定，并填进记录模板）：

```bash
python -m pip install -r requirements.txt
python doctor/serve.py
```

打开 `http://127.0.0.1:8765/`。服务器只监听本机，不写文件。

走查用的运行都在“夹具演示”里。**先不要告诉参与者这一点**——任务 1 要看他们自己
能不能看出来。

### 走查用到的运行

| 代号 | 列表里的名字 | 适配器场景（只给主持人） | 用于 |
| --- | --- | --- | --- |
| A | 复检记录 2（夹具） | `recheck-comparison` | 任务 1–7：一条完整的复检任务 |
| B | 复检记录 4（夹具） | `recheck-key-change-only` | 任务 8 |
| C | 复检记录 10（夹具） | `recheck-semantics-changed` | 任务 9 |
| C2 | 复检记录 9（夹具） | `recheck-requirement-relaxed` | 任务 9（第二遍） |
| D | 复检记录 7（夹具） | `recheck-producing-reissued` | 任务 10 |
| E | 复检记录 3（夹具） | `recheck-consuming-reissued` | 任务 10 |
| F | 复检记录 1（夹具） | `recheck-both-reissued` | 任务 10 |
| G | 复检记录 6（夹具） | `recheck-prior-without-basis` | 任务 11 |
| H | 复检记录 8（夹具） | `recheck-producing-reissued-content-changed` | 任务 13 |
| I | 复检记录 5（夹具） | `recheck-member-gone` | 任务 14 |

列表里的名字只有编号，故意不说每条记录是怎么来的：那正是参与者要从页面上读出来的。
念任务时只说“复检记录 N”，不说代号背后的场景，也不念第三列。

**每个场景给了什么（只给主持人，用来对照，不给参与者）**：B 改了一条没有被引用的
规则；C 改了一条被引用规则的数据类型；C2 放宽了一条被引用的规则；G 的原记录封存时
没有保存比较依据；D、E、F 分别是交出方、接收方、双方重新发布模型；H 是交出方重新
发布且部分检查结果变为通过；I 是交出方重新发布并删除了一个构件。这些原因大多**不在
记录里**（规则怎么改的，记录不携带），所以页面不会、也不应该说出来。

**已知的泄漏**：浏览器地址栏里仍然带着适配器的场景名（例如
`…/recheck-requirement-relaxed/…`），这是路由用的运行标识，界面改不了。走查时请把
浏览器调成不显示完整地址，或由主持人替参与者打开每条记录；参与者看到了地址的，
在记录里照实写。

B–I 各有 8 个子范围、13 件事；任务只要求参与者看其中指定的，其余不必逐件打开。

## 任务

逐条念给参与者。每条任务后请他们**用自己的话说出来**，主持人记原话。
参与者说“页面没说”“看不出来”是有效回答，照记。

### 第一部分：一条完整的复检任务（运行 A）

1. 请从入口进入，打开运行 A（念列表里的名字），再打开它的复检结果。
   这是真实项目的结果吗？你是从屏幕上哪里看出来的？
2. 不点任何链接。这次复检和上一次相比，**模型**有没有重新交过？是哪一方的？
3. 还是这一页。这次复检有几件事需要你看？有没有裁决变了的？
   其中有没有已经解决的？请指出你是根据哪一句话这么说的。
4. 打开第一件事。原来的问题是什么？现在这个问题**修好了吗**？
   请指出你的依据是哪一句。
5. 还是这一件事。上次用到的证据有几条？请逐条说：这一条现在是什么情况？
6. 这一件事，下一步该做什么？该谁来做？
   页面上能直接替你做哪一步？
7. 回到刚才的列表。你回到的是刚才那一件事的位置吗？

### 第二部分：其他情况（运行 B–I，各做对应的一条）

8. （运行 B）打开复检结果，进入第一件事，看旧证据。
   这些证据出问题了吗？你需要重新收集它们吗？这次交接还要不要复核？
9. （运行 C，然后运行 C2）打开复检结果。先不进任何一件事：
   这次复检，模型变了吗？有没有哪件事的裁决变了？
   旧的检查结果里有几条“有变化”？变的是什么？
   然后打开一件旧证据里带“有变化”的事。
   这能不能说明模型修好了？为什么？
   （C2 做完后）这两次有什么不同？
10. （运行 D、E、F，各做一遍）打开复检结果。
    这次是哪一方重新交了模型？这能不能说明洞口已经开好了？
    旧的检查结果现在是什么情况？旧的判定呢？这两样是一回事吗？
    做完三个之后：这三次有什么不同？
11. （运行 G）打开复检结果，进入第一件事，看旧证据。
    这些证据是丢了吗？
12. （任选一个运行）有没有哪个你想点、但页面上没有的操作？
    页面有没有告诉你它做不了？
13. （运行 H）打开复检结果。
    有几件事的裁决变了？从什么变成什么？
    模型里原来的问题修好了吗？你是从页面上哪里看出来的？哪里看不出来？
14. （运行 I）打开复检结果。有没有哪个构件不在了？
    它原来的问题算解决了吗？

## 主持人对照（不给参与者看）

用来判断参与者**有没有读错**，不是用来提示。读错的句子原样记进模板。

| 任务 | 屏幕上应能读出的内容 | 读成下面这样，记为读错 |
| --- | --- | --- |
| 1 | 不是真实结果：顶栏写“夹具演示”，下面一行写政策与判定为模拟 | “这是我们项目的结果” |
| 2 | 两侧模型都没有重新发布，版本未变 | “模型改过了” |
| 3 | 一件事；裁决变了的 0 项，它属于“记录没有给出当前对应子范围的”；没有已解决的——页面写明记录里没有“已解决”这个状态 | “已经解决了”“这项通过了” |
| 4 | 原来是 BLOCKED；现在这两个构件不再被配成一对检查。**没有被证明修好**：不等于开洞已建成，也不等于缺陷已修复 | “洞口开好了”“问题修复了” |
| 5 | 两条，都是“未找到对应证据”：本次记录没有再引用这两份判定。不代表问题已修复 | “证据丢了”“证据没问题” |
| 6 | 记录没有为这一对给出下一步，也没有责任角色可显示；页面建议核对让它不再配对的那份依据。页面不能替他做任何一步 | 说出一个页面上没有的负责人或动作 |
| 7 | 回到列表里这一件事的位置 | — |
| 8 | 只是引用换了键，证据内容没变，不必因此重新收集；**交接仍要复核** | “不用复核了” |
| 9 | 两次模型都没有重新发布。C：没有裁决变了的项；C2：1 项从 BLOCKED 变成 READY，页面写明“模型没有重新发布，裁决却变了，变化不来自模型改动”。两次都是 2 条检查结果“有变化”，其余 7 条只是换了键。C：只有检查要求变了，结果内容没变——不是同一条证据。C2：检查要求和结果内容都变了——变化可能来自要求被修改，**不能说模型修好了**；页面不说明要求是放宽还是收紧 | “结果一样，所以没问题”“变好了，所以模型修好了” |
| 10 | 各自说出是交出方、接收方还是双方；**都不能**说明洞口已开好。D、F：检查结果“有变化”，只有模型版本变了，内容没变。E：检查结果只是换了键；**判定是另一回事**——针对旧版本作出，不能归到新版本。双方重发时不把变化归到某一侧 | “对方重新交了，所以修好了”；E 里说“都没变” |
| 11 | 没有丢：是原记录没保存比较依据，所以无法比较 | “证据缺失”“证据没了” |
| 12 | 页面列出了做不了的五件事，没有对应按钮 | 以为某个链接能发起复检、关闭事项或打开 Revit |
| 13 | 7 项裁决变了：4 项 READY → UNKNOWN，3 项 BLOCKED → READY。6 条检查结果的内容变了、3 条只有模型版本变了；检查要求没变。**旧证据这一栏不说结果变好还是变差**，要看每件事的“当前裁决”。说“看不出来”是对的回答之一 | 只凭“内容变了”就说“修好了” |
| 14 | 有：3 件事的构件在重新发布的模型里被删除。**删除不等于修复**；它的旧证据是“无法比较”，不是证据丢了 | “删掉了，所以解决了” |

## 走查之后

- 记录交给技术总监与 PM；是否通过由他们判定，本脚本和 UI 工程师都不作结论。
- 读错的句子优先于“卡住但读对了”的地方：前者是页面说错了话，后者是页面说得慢。
- 同一处有两位以上参与者卡住或读错，记为需要改的措辞或布局，另开任务处理。
