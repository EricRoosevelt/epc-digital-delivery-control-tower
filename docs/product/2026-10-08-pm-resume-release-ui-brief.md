# 给技术总监：简历版本与一轮 UI 优化任务书

日期：2026-10-08，新加坡。用户已同意增加一轮 UI 优化及一天余量：10/14 冻结，10/15 完成简历素材。本文件可直接转交 TD，由 TD 下发 UI、Framework、README 和验证任务。本文不代表已向其他会话发送消息，也不代表 PM 已亲测最新 main。

## 1. 本轮目标与范围

招聘者打开项目后，10 秒内知道给谁用、解决什么问题；30 秒内找到一个具体问题及下一步；90 秒内看到复检前后的变化。这是体验目标，需要首次访客验证，不是尚未测量的宣传数字。

固定一版能启动、能走完、能解释的作品。优先做好桌面演示主线，同时保证手机可读、可操作。完成度来自连贯的信息、准确的状态和可靠的返回路径，不靠增加页面或装饰。

本轮冻结两条明确不同的路径：

1. **随附示例：理解交付判断与复检。** 首页 → 推荐示例 → 首次结果 → 一个具体事项 → 对应复检记录。示例中真实检查、模拟判断分别标清。这是浏览已有示例记录，不能演成刚刚上传、修改、重新运行产生的结果。
2. **自己的 IFC4：完成有限范围的真实检查。** 选文件 → 看清 PV-001 1.0 的适用范围和留存说明 → 运行 → 看结果及下一步。它不是通用质量检查，也不会自动得到示例里的全部交付判断。不要让入口、视频剪辑或简历措辞造成这种印象。

首页原有“随附项目检查尝试”保留为次要入口，拒绝页和返回路径必须完整。不要因多了本地 IFC 就堆出三张同等醒目的入口，让初访者自己猜应该选哪个。

这是用户批准的**简历展示范围调整**：全楼规模与 3D 不再是本次冻结的必要条件，原来的完整版本目标仍是 10/26。简历版本也属于对外展示，其实际展示范围的技术正确性、BIM 含义复核和发布批准不放松。不能把这次缩范围写成原全楼目标提前完成。

## 3. 页面任务：让用户先读到有用的内容

### README 与首页

README 开头是一句用途说明、一张最能体现产品价值的已复核截图、一个明确的体验入口。截图先选能同时看见具体问题、行动或复检变化的真实界面，不以空首页或后台统计代替价值。详细架构、长篇过程记录和大量截图放后面。

短介绍需让 BIM 从业者知道这是面向交付前检查与复检的个人开源项目。首页使用相同定位；不把 IDS、BCF、Pack、Overlay 等内部名词当作首次使用的先修知识。技术名词可在规则说明和追溯层保留。不得写“企业级”“全面检查”“自动修复”等无证据能力。

推荐动作是“先体验示例”；自己的 IFC 入口说明支持的格式与有限检查范围。首页简短交代“示例可看交付判断；自己的模型目前做 PV-001 检查”，避免用户上传后期待所有示例能力。

README 快速启动要从未安装项目的环境出发，说明支持的运行环境、依赖安装、启动、浏览器地址和停止方式。使用实际存在并亲测的命令，不能把维护者已经装好的 .venv 当作访客前置条件。至少提供完整英文主说明及对应的中文快速入口；语言链接不能是假入口。第一次安装遇到必要依赖时，应在运行前说明。

### 示例目录与结果列表

补回“每个示例是一份检查记录”的意思，合入一段简短介绍。推荐路径突出一个案例，其余示例仍可访问，名称说明它展示什么变化，不要求访客理解内部 fixture 名称。

结果页先回答“这次看到了什么、接下来处理什么”。统计必须沿用实际含义，检查结果、交付判断、事项数不能混成一个通过率；不能为了醒目把 UNKNOWN 或未评估变成绿色完成。

列表保留便于选项的信息：涉及的对象或可区分的事项名、工作结论、简短问题以及进入详情的动作。完整身份与长证据可展开。若用户必须逐个展开才能区分两项，就没有达到收起的目的。不要重新铺开已经收起的所有完整行动段落。

Q2 用短摘要说明当前来源和关键限制，详细来源展开查看。模拟标识和影响当前结论的限制仍可直接看见；全页不要反复贴同一段黄色长说明。普通来源提示和真正需要用户处理的错误，在视觉上应能区分。

### 单项详情与复检

阅读顺序保持一致：当前问题及结论 → 具体下一步／处理角色／复检所需证据 → 对象定位信息 → 详细依据与原始记录。对象的简短识别可出现在顶部，长身份表不压住行动。

复检先说本次相较上次发生了什么、什么仍未解决、接下来做什么。前后记录的顺序、名称和对比口径要明确。减少事项、对象消失或范围变化都不能直接显示为“已修复”。同时保留能够追溯结论的路径。

返回结果列表后，尽量保留原位置和展开状态；中英文切换保留当前对象和页面。不在用户处理到一半时跳回首页。二级标题、按钮叫法与页面内实际动作一致。

### 本地 IFC 与异常状态

选择文件前能读到支持 IFC4、PV-001 适用范围、文件与结果在本机的留存位置，以及如何清理。采用有层级的说明，不用一整屏条款阻挡操作；清理后不能再依赖什么仍要可找到。

运行时清楚表示正在检查，避免重复提交。没有可靠进度就不要显示虚构百分比或预计秒数。结果与 3D 分开就绪时，检查结果可先读。

必须走通并核对：成功获得结果、没有适用对象、不支持 schema、无几何对象、运行失败。区别处理：无适用对象不是通过；没有几何不等于没有检查结果；失败时用户知道可以如何修正或重新选择，而不是只得到内部异常栈。保留技术详情供追溯。

本轮不增加取消、拖拽、多文件管理等尚无实现的功能。已有能力的反馈与恢复优先；确需新增机制才能消除阻断时，TD 报具体缺口和成本。

## 4. 视觉与交互方向

采用安静、清楚的工程工具风格。沿用现有品牌和页面结构，统一标题层级、正文宽度、间距、边框、按钮与状态标识。重点内容有明确视觉重心，长键、模型标识和原始字段退到追溯层。不要新增营销大屏、无意义的 KPI 卡片或占据首屏的插画。

每一页有明确的主要动作，次要动作不过度竞争。状态用文字与样式共同表达，不能只靠红绿；键盘能进入与展开详情，焦点可见。链接和按钮在英文长文字下也不相互遮挡。

目标桌面视口 1440×900，同时核对 1280 宽；手机按 375×812 核对。不是把所有字段塞入首屏：首次／复检单项页应能看到具体行动的开头，目录看到首张可选示例；列表首屏则优先帮助理解概况和进入事项。不得靠缩小字体、裁切长句或隐藏限制达标。超长 ID、空值和英文换行不能把布局撑破。

## 8. 验收与交付材料

PM 验收看实际任务，不按截图张数判断完成。首次访客无需口头教学，应能说出：产品解决什么；当前哪些结果是真实检查、哪些是模拟；自己能用它检查什么；选中的事项怎么处理；复检究竟证明了什么变化。

TD 交付一份简短记录即可：候选完整 SHA、启动方法、推荐路径、前后对照（同样数据和视口）、关键正常／失败状态、实际成本、剩余问题、BIM 状态及技术审计结果。门禁由 TD 按 AGENTS.md 完整执行，UI 验收不替代技术审计，截图也不替代浏览器操作。

冻结版需要留存：

- 一份可准确复现的版本入口和运行说明；具体分支、标签与版本号由 TD 按仓库惯例准备，不把持续变化的 main 当冻结版本。
- 三张以内的核心截图：结果与行动、复检变化、本地 IFC 有限范围检查。每张附实际版本与简短说明；若 3D 获准纳入，可替换其中一张。
- 一段 60–90 秒演示：介绍问题 → 打开具体事项 → 看行动与依据 → 看复检变化；本地检查以单独片段说明范围。加载时长不伪造，剪辑不冒充实时连续运行。
- 一份与事实逐项对应的简历素材：已实现能力、经验证的技术特性、实际演示链接。样例统计不能包装成项目收益，测试数量不能替代用户价值，不宣称公司采用或商业部署。

全部公开素材只用许可允许再分发的样例，不展示 C2 私有模型、项目标识、路径或派生几何。冻结后发现含义或功能错误仍要修正并更新版本记录；稳定链接不意味着保留已知错误。
