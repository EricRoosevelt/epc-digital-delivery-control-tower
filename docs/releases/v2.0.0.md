# v2.0.0 — BIM Doctor: enterprise rules and purpose review

> Draft body for the GitHub Release. Before publishing, confirm that the tag
> points at the merge commit on `main` and that both CI jobs passed on that SHA.

BIM Doctor is now a local browser application for reviewing IFC model exchanges
against your own project rules and a declared delivery purpose. v1.0.0
(2026-08-16) was a deterministic IDS → BCF → Power BI pipeline over public
sample models. v2.0.0 keeps that pipeline and adds the review workflow on top.
This is a personal open-source portfolio project, not a production deployment
or a contractual model-acceptance decision.

## Highlights

**Project → project rules → model revision → purpose review**

- Create a project, download the editable rule template, and import one ZIP of
  native TOML rules plus a purpose manifest. The preview shows source, version,
  applicability, requirements and unsupported parts before anything runs.
  Adoption records a named confirmer and responsible reviewer/team and freezes
  that exact content as an immutable project version.
- Import one IFC into a model slot and save it as a revision. An unchecked-by-
  default option retains the exact original IFC in the local project library, so
  the purpose review opens without uploading the file again.
- Choose internal review, tender submission or a package-defined handover, then
  the revision and object scope. A purpose that needs a counterpart model asks
  for a real counterpart revision instead of inventing one.

**Unknown and coverage stay visible in purpose conclusions**

- Missing coverage, unsupported checks, absent evidence and an empty scope are
  reported as UNKNOWN; zero FAIL is not a readiness decision.
- READY is qualified to the listed purpose, evidence, version and scope. It is
  never a general project acceptance or an authenticated engineering signature.
- Problem cards show the element, requirement, observed value and next action
  before folded technical detail, and keep machine failures, human-evidence gaps
  and unexecuted checks apart.

**3D locate, focus and isolate**

- Load the bundled buildingSMART sample (39 elements, 32 renderable shapes) or
  one IFC file of up to 50 MB. Select a result to highlight its actual
  tessellated element, then focus or isolate it; click an element to read its
  checks. No geometry is invented for objects without a representation.
- Purpose-review blockers link to the rule and the exact element in the saved
  3D revision.

**Saved revisions and comparison**

- Saved revisions keep the report, rule snapshot and triangle geometry in a
  local SQLite library and reopen after a server restart without re-uploading.
- Record an owner, work status and note per result; status never changes
  PASS/FAIL. Download a Markdown work brief.
- Comparing two revisions distinguishes passed rechecks, remaining and new
  findings, elements not found, checks no longer applicable, and unavailable
  comparisons. Identity uses valid GlobalIds proven unique in the file, never
  names, tags or STEP IDs.

**Rechecks attribute the change**

- A successor review separates source-model changes, rule/configuration
  changes, scope changes, engine changes and new human evidence.
- Deletion, reclassification, exclusion or a changed rule basis is never
  counted as a repair. Saving a human judgment leaves the sealed conclusion
  unchanged until an explicit successor review.
- Human evidence needs an accepted method, recorder, reference and basis tied
  to the current model and scope; progress notes do not count as evidence.

**Long-running work you can cancel and retry**

- IFC imports and enterprise checks run in a supervised worker process with
  real stage and processed-element progress. Cancellation waits for the server
  to confirm the process tree stopped; the existing report and 3D view stay.
- Individual browser requests time out after 30 seconds. A lost status
  response resumes polling without starting a second import. The server
  enforces a 600-second job deadline by default (`--import-timeout-seconds`).
- Geometry request/JSON failures retry in place; a failed viewer module offers
  a page reload that keeps the record URL; startup has its own recovery notice.

**AI advice and local guidance**

- Local rule guidance works with no account or API key.
- Optional generated advice uses your own `OPENAI_API_KEY` and sends only the
  selected result's text evidence (rule, actual/expected values, element
  name/class/storey/tag and local guidance). IFC bytes, meshes, file paths and
  other findings are not sent. Suggestions never edit the model or change a
  status.

**Bilingual interface**

- The interface is available in Chinese and English.

## Known limitations

- **Real-model import time.** On one authorized real model (2,055 meshes,
  1,073,546 triangles), the current worker implementation completed two
  uncached native imports in 167.99 s and 166.86 s. That time ends at worker
  completion, before the browser shows the model. Under the earlier synchronous
  API, the same case took 179.5 s from upload to a usable UI. These are
  measurements on one host, not a capacity guarantee; the 50 MB upload cap is
  not a validated limit. See [the measured case](../handoffs/model-case.md).
- One earlier cold-load 3D failure lacks the evidence to establish its cause.
- Cross-revision pairing supports one IFC file per model slot. The public
  federated example can be saved and reopened but is not paired across
  revisions.
- Rule packages are a ZIP of native TOML rules and a JSON manifest. Excel, Word
  and PDF are not executable inputs.
- Single user on one computer: no authenticated team assignment, notifications,
  automatic source-model editing or project acceptance decision.
- Unsaved results use bounded temporary storage (four results / 256 MiB) and can
  expire. The in-memory cache is limited to 16 payloads / 64 MiB; saved revisions
  restore from SQLite.
- Live OpenAI advice requires your own account and may incur charges. CI uses
  no provider secret, so live calls are not part of the automated checks.

## Install

Python 3.14, Git and a browser with WebGL2. Windows and Ubuntu are verified in
CI. Keep the complete source checkout: the Python wheel does not contain the
browser application.

```bash
git clone https://github.com/EricRoosevelt/epc-digital-delivery-control-tower.git
cd epc-digital-delivery-control-tower
python3.14 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python doctor/serve.py --checks-dir "$HOME/.local/state/bim-doctor"
```

On Windows, clone with `git clone -c core.longpaths=true …` and follow the
[README quick start](../../README.md#quick-start).

## Upgrading from v1.0.0

- The pipeline's published data contract is now **1.7** (rule set 2.2).
  Canonical `finding_key` and `issue_key` values differ from earlier contract
  versions; the legacy CSV projections keep their identities. Each step is
  recorded in the [CHANGELOG](../../CHANGELOG.md).
- The PV-001 runtime predicate is v2. Comparing against a v1 result reports a
  changed rule basis rather than a repair; rerun both sources under v2.
- Project data lives in `<checks-dir>/projects/library.sqlite3`. Back up the
  whole external checks directory.
